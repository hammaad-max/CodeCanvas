User-Defined Methods & Overloading

Methods break a program into named, reusable blocks. ICSE tests method prototypes and signatures, actual and formal parameters, return values, pure and impure methods, call by value, and function overloading.

Core Concepts & Rules

Essential vocabulary and rules for user-defined methods:

Method Header (Prototype)

The first line of a method: access specifier, modifier, return type, name and parameter list, e.g. static int square(int n).

Method Signature

The method name plus its parameter list (number, types and order of parameters). The return type is not part of the signature.

Actual vs Formal Parameters

Actual parameters (arguments) are the values in the call: square(7). Formal parameters are the variables in the header that receive them: int n.

return Statement

Sends a value back to the caller and ends the method immediately. A void method returns no value.

Pure vs Impure Methods

A pure method does not change the state of any object or variable outside it (e.g. isEven). An impure method changes state, e.g. a setter.

Function Overloading

Several methods with the same name but different parameter lists. Java chooses which one to run from the arguments in the call. This is compile-time polymorphism.

Example Program

This program defines a returning method, three overloaded area() methods, a pure boolean method and a method that shows call by value.

Complete Java Program

public class MethodDemo {

    // Method with a parameter and a return value
    static int square(int n) {
        return n * n;
    }

    // Overloaded area() methods: same name, different parameter lists
    static double area(double radius) {
        return 3.14 * radius * radius;
    }

    static int area(int side) {
        return side * side;
    }

    static int area(int length, int breadth) {
        return length * breadth;
    }

    // Pure method: uses its parameter but changes nothing outside itself
    static boolean isEven(int n) {
        return n % 2 == 0;
    }

    // Call by value: changing the parameter does not change the caller's variable
    static void tryToChange(int x) {
        x = 100;
    }

    public static void main(String[] args) {
        System.out.println("square(7) = " + square(7));
        System.out.println("area(2.0) = " + area(2.0));
        System.out.println("area(5) = " + area(5));
        System.out.println("area(4, 6) = " + area(4, 6));
        System.out.println("isEven(9) = " + isEven(9));

        int value = 10;
        tryToChange(value);
        System.out.println("value after call = " + value);
    }
}

Understanding the Program Structure

1. Method Definitions

All the helper methods are written inside the class, outside main. They are static, so main can call them without creating an object.

2. Method Calls in main

main calls each method by name with actual parameters and prints the values they return.

How Does Java Execute This Program?

Execution trace showing the order in which statements run and how values change:

Step 1

square(7) copies 7 into n, computes 49 and returns it to the print statement.

Step 2

For each area call, Java matches the arguments to a signature: 2.0 (a double) chooses the circle version, 5 the square version and 4, 6 the rectangle version.

Step 3

isEven(9) returns 9 % 2 == 0, which is false.

Step 4

tryToChange(value) copies 10 into x and changes only that copy to 100, so value in main is still 10.

Line-by-Line Explanation

Line 4 — Method header

static int square(int n) {

int is the return type, square the name and int n the formal parameter. The signature is square(int).

Line 5 — Returning a value

return n * n;

The expression is evaluated, the result is sent back to the caller, and the method ends.

Line 17 — Overload with two parameters

static int area(int length, int breadth) {

Same name as the other two area methods but a different number of parameters, so it is a valid overload.

Line 23 — Boolean method

return n % 2 == 0;

The comparison already produces true or false, so no if-else is needed.

Line 39 — Call by value

tryToChange(value);

Primitive arguments are passed by value: the method gets a copy. Changes to x are lost when the method returns.

Expected Console Output

square(7) = 49
area(2.0) = 12.56
area(5) = 25
area(4, 6) = 24
isEven(9) = false
value after call = 10

Only the circle version prints a decimal result, because it is the only overload that returns a double. The last line proves that a primitive passed to a method cannot be changed by it.

ICSE Board Exam Tips & Common Traps

Keep these frequent exam traps in mind:

Return Type is Not Enough

Two methods that differ only in return type (int f(int) and double f(int)) are a compile error, not an overload.

Objects vs Primitives

Primitives are passed by value. When an array or object is passed, the method gets a copy of the reference, so it can change the array's contents (often called call by reference in ICSE).

Unreachable Code

A statement placed directly after return in the same block is a compile error because it can never run.
