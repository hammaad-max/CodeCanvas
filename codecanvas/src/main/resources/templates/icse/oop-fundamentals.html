OOP & Java Fundamentals

Java is an object-oriented language: programs are built from classes (blueprints) and objects (real instances created from them). This unit covers how Java code is compiled and run, the four principles of OOP, and how classes, objects and constructors work together.

Core Concepts & Rules

Essential principles tested in ICSE Section A theory and Section B programs:

Class and Object

A class is a blueprint (ICSE calls it an object factory) that defines data members and member methods. An object is an instance of a class, created with new, with its own state and behaviour.

Bytecode and the JVM

javac compiles .java source into platform-independent bytecode (.class). The JVM interprets that bytecode on any computer, which gives Java its "Write Once, Run Anywhere" property.

Encapsulation

Wrapping data and the methods that use it into one unit (a class). Making data private hides it from other classes; this is data hiding.

Abstraction

Showing only the essential features of an object and hiding the background details, e.g. calling display() without knowing how it prints.

Inheritance

One class (subclass) acquires the members of another (superclass) using extends. It promotes code reuse.

Polymorphism

One name, many forms. In ICSE this is mainly method overloading: several methods with the same name but different parameter lists.

Example Program

This program defines a Book class with data members, a parameterised constructor and a method, then creates two separate objects from it.

Complete Java Program

public class Book {

    // Instance variables: every object gets its own copy
    String title;
    int pages;
    double price;

    // Parameterised constructor: same name as the class, no return type
    Book(String t, int p, double pr) {
        title = t;
        pages = p;
        price = pr;
    }

    // Member method that uses the object's own data
    void display() {
        System.out.println(title + " has " + pages + " pages and costs Rs. " + price);
    }

    public static void main(String[] args) {
        Book b1 = new Book("Java Basics", 240, 350.0);
        Book b2 = new Book("Data Structures", 410, 525.5);
        b1.display();
        b2.display();
        System.out.println("b1 and b2 are different objects: " + (b1 != b2));
    }
}

Understanding the Program Structure

1. The Class Definition

public class Book declares the blueprint. Its data members (title, pages, price) describe a book; its methods describe what a book can do.

2. The main Method

public static void main(String[] args) is where execution starts. It is static so the JVM can call it without creating a Book object first.

How Does Java Execute This Program?

Execution trace showing the order in which statements run and how values change:

Step 1

The JVM loads Book.class (the bytecode) and calls main.

Step 2

new Book("Java Basics", 240, 350.0) allocates a new object in memory and runs the constructor, which copies the arguments into that object's fields.

Step 3

A second new creates a completely separate object b2 with its own copy of title, pages and price.

Step 4

b1.display() and b2.display() each print their own object's data; finally the two references are compared and found to be different objects.

Line-by-Line Explanation

Line 4 — Instance variables

String title;

Declared inside the class but outside any method, so they belong to each object. Their default values are null, 0 and 0.0 until the constructor sets them.

Line 9 — Parameterised constructor

Book(String t, int p, double pr) {

A constructor has the same name as the class and no return type (not even void). It runs automatically when an object is created and initialises its fields.

Line 21 — Creating an object

Book b1 = new Book("Java Basics", 240, 350.0);

new allocates memory and calls the constructor. b1 is a reference that stores where the object lives.

Line 23 — Calling a method on an object

b1.display();

The dot operator invokes display() on the object that b1 refers to, so it prints b1's title, pages and price.

Line 25 — Comparing references

System.out.println("b1 and b2 are different objects: " + (b1 != b2));

!= on objects compares references (memory locations), not contents. The two objects are separate, so the result is true.

Expected Console Output

Java Basics has 240 pages and costs Rs. 350.0
Data Structures has 410 pages and costs Rs. 525.5
b1 and b2 are different objects: true

Each object prints its own values, which shows that objects created from one class keep separate state. Note that 350.0 prints with .0 because it is a double.

ICSE Board Exam Tips & Common Traps

Keep these frequent exam traps in mind:

💡 Constructor vs Method

If you write void Book(), it is an ordinary method, not a constructor. Constructors never have a return type.

💡 Default Constructor

Java supplies a default (no-argument) constructor only if you write no constructor at all. Once you write a parameterised one, new Book() no longer compiles.

💡 Platform Independence

Bytecode is platform independent; the JVM is platform dependent (each operating system has its own JVM). Board questions often ask which is which.
