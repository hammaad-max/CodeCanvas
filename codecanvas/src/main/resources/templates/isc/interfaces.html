Interfaces & Abstract Classes

Abstract classes and interfaces describe what objects must be able to do without fixing exactly how. They are how Java models general ideas such as "an employee" or "something that can be paid", and ISC tests their rules and differences.

Core Concepts & Rules

Essential rules for abstract classes and interfaces:

Abstract Class

Declared with abstract. It cannot be instantiated with new, may contain both abstract and normal methods, and can have constructors and instance variables.

Abstract Method

A method with no body, e.g. abstract String role();. Every concrete (non-abstract) subclass must override it.

Interface

Declared with interface. Its methods are public and abstract by default, and its variables are public static final constants.

implements

A class uses implements to promise it provides all the interface's methods. A class can implement several interfaces, which is how Java achieves multiple inheritance of type.

Abstract Class vs Interface

Use an abstract class for closely related classes that share code and state. Use an interface for a capability that unrelated classes can share.

References to Abstract Types

You cannot write new Employee(), but you can declare Employee e = new Manager(...); or Payable p = new Intern(...);.

Example Program

This program combines an interface, an abstract class that implements it, and two concrete subclasses, then uses both abstract types as references.

Complete Java Program

interface Payable {
    double TAX_RATE = 0.10;              // public static final constant
    double pay();                        // public and abstract by default
}

abstract class Employee implements Payable {
    protected String name;

    Employee(String name) {
        this.name = name;
    }

    abstract String role();              // subclasses must implement this

    void show() {
        System.out.println(name + " (" + role() + ") earns " + pay());
    }
}

class Manager extends Employee {
    private double salary;

    Manager(String name, double salary) {
        super(name);
        this.salary = salary;
    }

    String role() {
        return "Manager";
    }

    public double pay() {
        return salary - salary * TAX_RATE;
    }
}

class Intern extends Employee {
    private int hours;

    Intern(String name, int hours) {
        super(name);
        this.hours = hours;
    }

    String role() {
        return "Intern";
    }

    public double pay() {
        return hours * 200.0;
    }
}

public class PayrollTest {
    public static void main(String[] args) {
        Employee[] staff = { new Manager("Asha", 50000), new Intern("Ravi", 40) };
        for (Employee e : staff) {
            e.show();
        }
        Payable p = new Intern("Meera", 10);
        System.out.println("Payable pay = " + p.pay());
    }
}

Understanding the Program Structure

1. Contract and Partial Implementation

Payable defines what must exist (a pay() method). Employee implements part of the behaviour (show()) but leaves role() and pay() to its subclasses.

2. Concrete Classes

Manager and Intern fill in every missing method, so only they can be created with new.

How Does Java Execute This Program?

Execution trace showing the order in which statements run and how values change:

Step 1

Creating a Manager runs Employee's constructor through super(name), then stores the salary.

Step 2

show() (written in Employee) calls role() and pay(), which are dispatched to the Manager versions: 50000 − 5000 = 45000.0.

Step 3

For the intern, pay() is 40 × 200.0 = 8000.0, so the second line shows Ravi's pay.

Step 4

A Payable reference can hold any implementing object; p.pay() runs Intern's version and gives 2000.0.

Line-by-Line Explanation

Line 2 — Interface constant

double TAX_RATE = 0.10;              // public static final constant

Interface variables are automatically constants. Every implementing class can use TAX_RATE directly but cannot change it.

Line 6 — Abstract class implementing an interface

abstract class Employee implements Payable {

An abstract class does not have to implement every interface method; it can leave pay() to its subclasses.

Line 13 — Abstract method

abstract String role();              // subclasses must implement this

No body, just a semicolon. Manager and Intern would fail to compile without their own role().

Line 32 — public is required

public double pay() {

Interface methods are public, and an overriding method cannot be less accessible, so the public keyword is mandatory here.

Line 60 — Interface as a type

Payable p = new Intern("Meera", 10);

The variable can only call Payable methods, but the object is a full Intern.

Expected Console Output

Asha (Manager) earns 45000.0
Ravi (Intern) earns 8000.0
Payable pay = 2000.0

One show() method produces the right role and pay for each subclass, because the abstract methods are filled in differently in each one.

ISC Board Exam Tips & Common Traps

Keep these frequent exam traps in mind:

Cannot Instantiate

new Employee("X") and new Payable() are compile errors, even though both types can be used for variables and arrays.

Weaker Access Error

Implementing an interface method without public is a compile error ("attempting to assign weaker access privileges").

Abstract Needs No Abstract Methods

A class can be declared abstract with no abstract methods, purely to stop it being instantiated. But any class with an abstract method must be abstract.
