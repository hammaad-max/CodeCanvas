Classes, Objects & Wrapper Classes

ISC builds on ICSE by treating classes as proper data types: private data members, constructor overloading, the this keyword, static members shared by all objects, and wrapper classes that turn primitives into objects.

Core Concepts & Rules

Essential rules tested in ISC Paper 1 and the practical paper:

Instance vs Static Members

Each object has its own copy of an instance variable. A static variable has a single copy shared by every object of the class, and a static method can be called without an object.

Constructor Overloading

A class can have several constructors with different parameter lists. this(...) lets one constructor call another; it must be the first statement.

The this Keyword

this refers to the current object. this.balance = balance separates the data member from a parameter with the same name.

Access Specifiers

private: same class only. Default (no keyword): same package. protected: same package plus subclasses. public: everywhere.

toString()

If a class defines public String toString(), printing an object (or joining it to a String) automatically uses that text.

Wrapper Classes

Integer, Double, Character, etc. wrap primitives as objects. Integer.parseInt("125") converts text to a number; autoboxing and unboxing convert automatically.

Example Program

This program models a bank account with private data, two constructors linked by this(...), a static object counter and toString(), then shows wrapper-class conversions.

Complete Java Program

public class Account {

    private String holder;
    private double balance;
    private static int count = 0;   // one copy shared by all objects

    // Default constructor delegates to the parameterised one
    Account() {
        this("Unknown", 0.0);
    }

    // Parameterised constructor
    Account(String holder, double balance) {
        this.holder = holder;       // 'this' separates field from parameter
        this.balance = balance;
        count++;
    }

    void deposit(double amount) {
        balance += amount;
    }

    public String toString() {
        return holder + ": Rs. " + balance;
    }

    public static void main(String[] args) {
        Account a = new Account("Riya", 500.0);
        Account b = new Account();
        a.deposit(250.0);

        System.out.println(a);
        System.out.println(b);
        System.out.println("Accounts created: " + Account.count);

        // Wrapper classes: converting between text, primitives and objects
        int n = Integer.parseInt("125");
        Integer boxed = n;              // autoboxing
        int back = boxed + 5;           // unboxing
        System.out.println("parsed + 5 = " + back);
        System.out.println("Max int = " + Integer.MAX_VALUE);
        System.out.println("Double.toString(2.5) = " + Double.toString(2.5));
    }
}

Understanding the Program Structure

1. Encapsulated Data

The data members are private, so other classes can only change them through methods like deposit(). This is encapsulation and data hiding.

2. Object Lifecycle

Constructors initialise each new object, instance methods act on one object, and the static counter records how many objects have been created in total.

How Does Java Execute This Program?

Execution trace showing the order in which statements run and how values change:

Step 1

new Account("Riya", 500.0) runs the parameterised constructor; count becomes 1.

Step 2

new Account() runs the default constructor, which calls this("Unknown", 0.0); the parameterised constructor runs again and count becomes 2.

Step 3

a.deposit(250.0) changes only a's balance to 750.0. Printing a and b calls their toString() methods.

Step 4

parseInt turns "125" into 125, it is boxed into an Integer and unboxed again for + 5, giving 130.

Line-by-Line Explanation

Line 5 — Static data member

private static int count = 0;   // one copy shared by all objects

There is only one count no matter how many objects exist, so every constructor call adds to the same variable.

Line 9 — Constructor chaining

this("Unknown", 0.0);

Calls the other constructor of the same class. It must be the first statement, and it avoids repeating the initialisation code.

Line 14 — Resolving a name clash

this.holder = holder;       // 'this' separates field from parameter

Inside the constructor, plain holder means the parameter. this.holder means the object's data member.

Line 23 — Overriding toString()

public String toString() {

println(a) calls a.toString() automatically. Without it, Java would print something like Account@1b6d3586.

Line 38 — Autoboxing

Integer boxed = n;              // autoboxing

Java wraps the int in an Integer object automatically. Using it in arithmetic unboxes it back to an int.

Expected Console Output

Riya: Rs. 750.0
Unknown: Rs. 0.0
Accounts created: 2
parsed + 5 = 130
Max int = 2147483647
Double.toString(2.5) = 2.5

The counter shows 2 even though this(...) was used, because the counting code lives in one constructor that both objects pass through.

ISC Board Exam Tips & Common Traps

Keep these frequent exam traps in mind:

💡 Static Cannot Use Instance

A static method cannot use instance variables or this directly, because it is not running for any particular object.

💡 this() Must Be First

this(...) anywhere except the first line of a constructor is a compile error.

💡 parseInt Errors

Integer.parseInt("12a") compiles but throws NumberFormatException at run time.
