Stacks, Queues & Linked Lists

Data structures organise data for efficient access. ISC requires array-based stacks and queues with overflow and underflow checks, and linked lists built from self-referential node classes.

Core Concepts & Rules

Essential definitions and operations:

Stack (LIFO)

Last In, First Out. Items are added with push and removed with pop at one end, the top. Used for undo, recursion and expression evaluation.

Queue (FIFO)

First In, First Out. Items are added at the rear (enqueue) and removed from the front (dequeue), like a line of people.

Overflow and Underflow

Overflow: adding to a full structure. Underflow: removing from an empty one. Both must be checked before every push/pop or enqueue/dequeue.

Circular Queue and Deque

A circular queue reuses freed space with rear = (rear + 1) % size. A deque (double-ended queue) allows insertion and deletion at both ends.

Linked List

A chain of nodes, each holding data and a reference (next) to the following node. The list grows and shrinks at run time, unlike a fixed-size array.

Self-Referential Class

class Node { int data; Node next; } contains a reference to its own type. The last node's next is null.

Example Program

This program implements an array-based stack and queue with overflow and underflow checks, and builds and traverses a three-node linked list.

Complete Java Program

class Stack {
    private int[] arr;
    private int top;

    Stack(int size) {
        arr = new int[size];
        top = -1;                        // -1 means the stack is empty
    }

    void push(int v) {
        if (top == arr.length - 1) {
            System.out.println("Stack Overflow");
            return;
        }
        arr[++top] = v;
    }

    int pop() {
        if (top == -1) {
            System.out.println("Stack Underflow");
            return -9999;
        }
        return arr[top--];
    }
}

class Queue {
    private int[] arr;
    private int front, rear;

    Queue(int size) {
        arr = new int[size];
        front = 0;
        rear = -1;
    }

    void enqueue(int v) {
        if (rear == arr.length - 1) {
            System.out.println("Queue Overflow");
            return;
        }
        arr[++rear] = v;
    }

    int dequeue() {
        if (front > rear) {
            System.out.println("Queue Underflow");
            return -9999;
        }
        return arr[front++];
    }
}

class Node {
    int data;
    Node next;                           // reference to the next node

    Node(int data) {
        this.data = data;
    }
}

public class DataStructures {
    public static void main(String[] args) {
        Stack s = new Stack(3);
        s.push(10);
        s.push(20);
        s.push(30);
        s.push(40);
        System.out.println("Popped: " + s.pop() + ", " + s.pop());

        Queue q = new Queue(3);
        q.enqueue(1);
        q.enqueue(2);
        q.enqueue(3);
        System.out.println("Dequeued: " + q.dequeue() + ", " + q.dequeue());

        // Linked list 5 -> 15 -> 25, then traverse it
        Node head = new Node(5);
        head.next = new Node(15);
        head.next.next = new Node(25);
        System.out.print("Linked list: ");
        for (Node cur = head; cur != null; cur = cur.next) {
            System.out.print(cur.data + (cur.next != null ? " -> " : "\n"));
        }
    }
}

Understanding the Program Structure

1. Data Structure Classes

Stack, Queue and Node each keep their data private (or simple) and expose only the operations that make sense for that structure.

2. The Test Driver

DataStructures.main exercises each structure, including a push onto a full stack to show the overflow check.

How Does Java Execute This Program?

Execution trace showing the order in which statements run and how values change:

Step 1

Pushing 10, 20 and 30 fills the 3-slot stack (top becomes 2). Pushing 40 finds top == 2 and prints "Stack Overflow" instead.

Step 2

Two pops return the most recent items first: 30 then 20 (LIFO).

Step 3

Enqueuing 1, 2, 3 fills the queue; two dequeues return the oldest items first: 1 then 2 (FIFO).

Step 4

Three nodes are linked with next references; the loop follows them from head until it reaches null.

Line-by-Line Explanation

Line 11 — Overflow check

if (top == arr.length - 1) {

The stack is full when top is the last valid index. Checking first prevents an ArrayIndexOutOfBoundsException.

Line 15 — Push with pre-increment

arr[++top] = v;

top moves up first and then the value is stored there, so the first push uses index 0.

Line 23 — Pop with post-decrement

return arr[top--];

The top value is returned and then top moves down. The array slot is not erased; it is simply no longer part of the stack.

Line 46 — Underflow check for a queue

if (front > rear) {

When front has moved past rear, every item has been removed and the queue is empty.

Line 83 — Traversing a linked list

for (Node cur = head; cur != null; cur = cur.next) {

Start at the head and follow each next reference. Losing head would make the whole list unreachable.

Expected Console Output

Stack Overflow
Popped: 30, 20
Dequeued: 1, 2
Linked list: 5 -> 15 -> 25

The overflow message appears first because it is printed during the fourth push, before any pop happens. The pop and dequeue lines show LIFO and FIFO order side by side.

ISC Board Exam Tips & Common Traps

Keep these frequent exam traps in mind:

Empty Stack Value

Memorise the conventions: an empty stack has top = -1; a simple queue is empty when front > rear (or when both are -1, depending on the textbook version).

Simple Queue Wastes Space

In a linear array queue, slots freed by dequeue are never reused. That is the reason circular queues exist, and a common theory question.

Inserting into a Linked List

To insert at the beginning: newNode.next = head; head = newNode; in that order. Reversing the order loses the rest of the list.
