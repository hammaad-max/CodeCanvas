Inheritance & Polymorphism

Inheritance lets a subclass reuse and extend a superclass. Combined with method overriding it gives run-time polymorphism: one superclass reference can call the right version of a method for whatever object it points to. ISC regularly asks for a superclass and subclass program in Section C.

Core Concepts & Rules

Essential rules for inheritance questions:

extends

class Rectangle extends Shape makes Rectangle a subclass. It inherits all non-private members of Shape. Java supports single inheritance of classes only.

super Keyword

super(...) calls the superclass constructor and must be the first statement. super.method() calls the superclass version of an overridden method.

Method Overriding

A subclass method with the same signature as a superclass method replaces it for subclass objects. @Override asks the compiler to check this.

Overloading vs Overriding

Overloading: same name, different parameters, same class, decided at compile time. Overriding: same signature, subclass, decided at run time.

Dynamic Method Dispatch

With Shape s = new Circle(2);, calling s.area() runs Circle's area(), because the object's type decides at run time.

protected and instanceof

protected members are visible in subclasses. obj instanceof Type tests whether an object is of a type or one of its subtypes.

Example Program

This program defines a Shape superclass and two subclasses that override area(), then processes them through an array of superclass references.

Complete Java Program

class Shape {
    protected String name;

    Shape(String name) {
        this.name = name;
    }

    double area() {
        return 0.0;
    }

    void describe() {
        System.out.println(name + " with area " + area());
    }
}

class Rectangle extends Shape {
    private double length, breadth;

    Rectangle(double length, double breadth) {
        super("Rectangle");              // must be the first statement
        this.length = length;
        this.breadth = breadth;
    }

    @Override
    double area() {
        return length * breadth;
    }
}

class Circle extends Shape {
    private double radius;

    Circle(double radius) {
        super("Circle");
        this.radius = radius;
    }

    @Override
    double area() {
        return 3.14 * radius * radius;
    }
}

public class ShapeTest {
    public static void main(String[] args) {
        Shape[] shapes = { new Rectangle(4, 5), new Circle(2), new Shape("Blank") };
        for (Shape s : shapes) {
            s.describe();                // each object's own area() runs
        }
        Shape s = new Circle(1);
        System.out.println(s instanceof Circle);
        System.out.println(s instanceof Shape);
    }
}

Understanding the Program Structure

1. A Class Hierarchy

Shape holds what every shape shares (a name and describe()). Rectangle and Circle add their own data and override area().

2. Superclass References

The array has type Shape[] but stores subclass objects. This is legal because a Rectangle is a Shape.

How Does Java Execute This Program?

Execution trace showing the order in which statements run and how values change:

Step 1

new Rectangle(4, 5) first runs super("Rectangle") to set the name, then stores length and breadth. Circle(2) works the same way.

Step 2

The loop calls describe(), which is only written in Shape, on every element.

Step 3

Inside describe(), the call area() is dispatched at run time: Rectangle gives 20.0, Circle gives 12.56, and the plain Shape gives 0.0.

Step 4

s refers to a Circle, so it is an instance of both Circle and its superclass Shape.

Line-by-Line Explanation

Line 17 — Inheriting from a superclass

class Rectangle extends Shape {

Rectangle automatically has name and describe() without redeclaring them.

Line 21 — Calling the superclass constructor

super("Rectangle");              // must be the first statement

Constructors are not inherited, so the subclass constructor passes the name up to Shape's constructor.

Line 26 — Overriding a method

@Override

The annotation makes the compiler confirm that a matching superclass method exists, which catches spelling mistakes in the signature.

Line 50 — Polymorphic call

s.describe();                // each object's own area() runs

The same line of code produces different results for each element, depending on the actual object.

Line 53 — Type testing

System.out.println(s instanceof Circle);

instanceof checks the object, not the reference variable, so it is true even though s is declared as a Shape.

Expected Console Output

Rectangle with area 20.0
Circle with area 12.56
Blank with area 0.0
true
true

describe() exists only in Shape, yet it prints the correct area for each subclass. That is dynamic method dispatch in action.

ISC Board Exam Tips & Common Traps

Keep these frequent exam traps in mind:

💡 Reference Type Limits

Through a Shape reference you can only call methods that Shape declares. Subclass-only methods need a cast: ((Circle) s).method().

💡 Private Members

Private members of the superclass are not accessible in the subclass, even though they exist in the object. Use protected or a getter.

💡 Static Methods

Static methods are not overridden (they are hidden), so dynamic dispatch does not apply to them.
